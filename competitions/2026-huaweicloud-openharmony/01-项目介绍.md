# 项目介绍：基于 OpenHarmony 的存量工业设备只读采集网关

## 1. 背景与痛点

温州泵阀、低压电气、汽摩配等制造企业的存量设备普遍只有 RS485 现场总线，品牌与协议各不相同。要做数字化改造，通常面临三个现实问题：

- 原厂协议不开放，读写一体的改造需要授权，周期长；
- 直接介入原控制回路风险高，企业担心影响生产；
- 整体替换设备成本过高，中小企业难以承受。

因此，市场真正缺的不是"更强的控制器"，而是一套**企业敢先试、试得起**的低成本数据采集方案。

## 2. 方案概述

在存量设备旁外挂一个采集模组，**只读**获取设备数据，再上报到运维看板。全链路：

```text
工业设备（PLC / 仪表）
        │  RS485，Modbus RTU 只读
        ▼
   MAX3485 收发器
        │
        ▼
Hi3861（OpenHarmony 轻量系统）
  解析 → 校验 → 阈值判断
        │  2.4GHz Wi-Fi + MQTT
        ▼
   本地运维看板
```

三条明确约束：**不写寄存器、不控制设备、不接原控制回路**。硬件上只并联 A/B 两根总线，设备原有运行逻辑不受影响。

## 3. 关键设计

| 设计 | 说明 |
| --- | --- |
| 只读接入 | 仅使用 Modbus 功能码 `0x03` 读保持寄存器，从机制上排除误操作风险 |
| 三层解耦 | 业务层、协议层、设备层分离；换设备只改点位表（约 20 行），换协议只加一个实现文件 |
| 协议可插拔 | 协议层抽象为函数指针表，新增 Modbus TCP 等协议时主循环零改动 |
| 数据可靠性 | 每帧经过长度、功能码/字节数、CRC16、异常码四道校验，脏数据不会进入业务层 |
| 收发时序 | RS485 方向控制在帧末字节移出后才释放，避免帧被截断导致的偶发通信失败 |
| 整数缩放 | 上报原始值 + 缩放因子，由接收端换算工程量，避免轻量系统上的浮点开销与精度问题 |
| 上报自愈 | MQTT 发送失败自动断线重连并重发一次，不阻塞主循环 |
| 可验证 | 提供三阶段有界自动验收脚本，每阶段超时、退出必释放串口，演示前可反复执行 |

## 4. 演示与验收

- **正常采集**：温度、湿度、状态三个点位按周期上报，看板显示原始值与工程量。
- **阈值告警**：从站数值越限后，告警消息走独立主题，看板对应行变红；恢复后自动转回正常。
- **自动验收**：一条命令完成"正常点位 → 阈值告警 → 告警恢复"三阶段校验，输出各阶段耗时与通过结果。
- **无硬件模式**：没有开发板和 RS485 时，可用纯软件模拟数据源驱动看板，便于分离排查问题。

## 5. 适用场景

泵阀、低压电气、汽摩配等存量设备的运行状态监测；车间设备联网试点；需要"零风险、低成本"起步的数字化改造项目。

## 6. 边界与后续工作

- 目前仅与 PC 模拟从站完成端到端联调，接入真实设备需按手册核对站号、寄存器、缩放与阈值；
- 单从站 3 个点位、逐点单寄存器读取，点位规模扩大后应改为批量读；
- 告警暂无回差与持续时间过滤，阈值附近抖动可能反复告警；
- 数据未做持久化，看板重启后清空；
- 长时间连续运行与采集成功率统计尚未完成。

后续计划：批量读优化、告警迟滞、多设备调度、云 MQTT 接入与 TLS/ACL 安全加固。
